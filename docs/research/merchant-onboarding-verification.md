# 商家入驻、发布者实名与资质核验研究

> 核对日期：2026-09-02。本文区分“法律/规章明文”和“针对本次整改的实务建议”，用于制定整改流程，不代替主管部门针对个案的最终口径或律师正式法律意见。

## 一、结论先行

1. **目前不需要为了完成整改而技术对接国家企业信用信息公示系统。**现行规则要求平台核验、登记、建档和定期更新，但没有规定核验只能通过系统 API 完成。《网络交易监督管理办法》第二十五条对开放数据接口的表述是“鼓励”，而且对象是向市场监管部门自动化报送信息，不是强制平台用接口查询企业。因此，现阶段采用“商户上传材料 + 审核人员登录官方公示系统人工查询比对 + 保存查询时间、结果截图和审核记录”是可行方案。
2. **商家入驻协议可以纸质签，也可以电子签。**法律没有要求商家入驻协议必须采用纸质手写形式；数据电文可构成书面形式，可靠电子签名与手写签名或盖章具有同等法律效力。但监管意见已经明确要“双方签署”的样本，为降低解释和举证成本，本次首批 1—2 份建议采用“双方加盖公章的纸质扫描件”或“可验证签名证书和签署报告的可靠电子签 PDF”，不要只提交一个“我已阅读”的勾选页面。
3. **平台运营主体本身的业务只能作为“自营”样本，不能作为双方商家入驻协议样本。**同一统一社会信用代码代表同一民事主体，无法证明两个主体之间真实签署了入驻协议；且平台开展自营业务依法应显著标记“自营”。
4. **关联但不同主体的真实企业可以作为初期样本。**只要企业具有不同的统一社会信用代码、真实存续、经营范围/许可与发布内容相符，完成真实账号、授权经办人、协议签署、人工核验和真实信息发布，即可形成可核验样本。建议在说明中主动披露关联关系；如果同一自然人同时代表双方，最好改由双方分别授权的不同经办人签署并各自加盖公章，保留授权文件。
5. 监管意见中“提交 1—2 份网站中发布者已完成实名、资质认证的后台截图”，本质上是要看**平台已经实际执行审核，而不仅是网站上增加了一个表单**。截图应把发布内容、账号、主体、审核结果和时间串起来，但身份证号、手机号、证件原图等不应在普通截图中完整暴露。

## 三、是否需要对接国家企业信用信息公示系统

### 法律结论

现行《电子商务法》第二十七条和《网络交易监督管理办法》第二十四条只规定“进行核验”，没有指定唯一技术路线。《网络交易监督管理办法》第二十五条的原文是“**鼓励**网络交易平台经营者与市场监督管理部门建立开放数据接口等形式的自动化信息报送机制”，且该条讨论的是报送。因此，不能把“应核验”解释成“现阶段必须采购接口或与公示系统直连”。

国家企业信用信息公示系统是法定的企业信用信息归集公示平台，可作为人工核验的主要官方来源；市场监管总局对其定位见[《关于进一步优化国家企业信用信息公示系统的通知》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/xyjgs/art/2023/art_077815c7b2dd4aaf8cbed016d72d5bda.html)，查询入口可从[市场监管总局政务服务平台](https://zwfw.samr.gov.cn/eportal/ui?pageId=89123c831db942a7b831539b5d763603)进入。

截至核对日，强制性国家标准《网络交易平台履行主体资质审核公示义务基本要求》仍显示为国家标准**项目**，不是已发布实施的标准。项目内容同时列出联网核查、信息比对、人证卡一致性审查和人工复核等方法，说明未来方向是多种核验手段和系统化留痕，而非只有一种查询方式。应持续关注其后续发布状态，不能把项目介绍提前当作现行强制条文。见[全国标准信息公共服务平台项目页](https://std.samr.gov.cn/gb/search/gbDetailed?id=48E3B36F37C371E4E06397BE0A0A7AEE)。

### 现阶段可执行的人工核验流程（实务建议）

1. 商户在线填写法定全称、统一社会信用代码、注册地址、实际经营地址、联系方式、法定代表人、业务范围，并上传营业执照；涉及许可业务的，同时上传行政许可或专业资质。
2. 企业账号经办人提交本人实名信息及企业授权书；身份证件用于后台核验和内部保存，不能公开展示。
3. 审核人员通过官方公示系统按企业名称和统一社会信用代码查询，逐项比对名称、代码、登记状态、法定代表人、住所、经营范围，并查看经营异常、严重违法失信等公开状态；行业许可还应到对应主管部门官方查询渠道复核。
4. 后台记录查询渠道、查询时间、审核人、匹配项、不一致项、处理意见和下一次复核日期，并保存带日期的官方查询结果截图/PDF。若查不到、主体已注销/吊销、名称或代码不一致、经营范围明显不支持发布业务，应驳回或要求补正，不得先发布后补材料。
5. 审核通过后才开放发布/开店权限；企业信息变更时重新核验，常规复核间隔不得超过六个月。

当商户数量增加后，再考虑接入企业身份/电子营业执照核验服务以降低人工成本和漏检率；这属于效率和风控升级，不是本次整改通过的前置法律条件。

## 四、商家怎样获取、签署并留档入驻协议

### 推荐流程（实务建议）

1. 在“商家入驻”页面提供当前版本协议的在线阅读和 PDF 下载，页面显示协议名称、版本号、生效日期、平台运营主体全称。
2. 商家先提交主体和资质材料；平台预审通过后，由系统生成已填入双方主体信息、商家账号/店铺标识和协议版本的定稿，避免空白通用协议无法对应具体商家。
3. 二选一签署：
   - **首批整改样本优先**：平台和商家分别加盖公章，填写签署日期；经办人签字时附企业授权书。各方各留原件，平台保存彩色扫描 PDF。
   - **长期线上方案**：通过能够验证签名人身份、签署意愿、签署后篡改且可导出签名证书/签署报告的电子签服务，由双方企业签署。保存完整 PDF、签名验证结果、签署时间、签署人身份/授权、协议哈希和版本号。
4. 只有协议签署和资质审核均完成后，后台状态才改为“审核通过”，并开放信息发布或店铺功能。
5. 将协议、营业执照/许可、授权书、公示系统查询记录、审核记录、账号与发布内容的对应关系组成一个档案包。建议贯穿合作期保存，并至少保存至商家退出后三年；协议历史版本按规章要求单独保留。

线上同意动作必须由商家主动完成，不得默认勾选；即使后续采用可靠电子签，仍应保存商家所见的完整协议版本及主动发起/确认签署的记录。

协议至少写清：双方企业全称、统一社会信用代码和地址；商家账号/店铺名称；准入、退出和复核机制；允许发布的商品/服务范围；行政许可保证；内容真实性；消费者权益、个人信息和知识产权责任；平台审核、下架、暂停/终止服务措施；费用结算（如有）；违约责任；争议解决；协议版本和生效日期。

### 本次提交 1—2 份样本的材料组合

每个商家单独成包并用同一编号贯穿，例如 `M-202609-001`：

- 双方已签署的入驻协议；
- 商家营业执照，以及与实际发布内容相关的行政许可/专业资质；
- 经办人实名结果和授权书（对外副本脱敏）；
- 国家企业信用信息公示系统查询结果及查询日期；
- 后台审核通过截图；
- 网站上该商家公开页/信息详情页截图和 URL，企业名称应与执照一致；
- 审核台账摘要，包括审核人、审核时间、结论、下次复核日期。

## 五、能否用“我们自己的企业”作为样本

### 1. 与平台运营主体是同一企业、同一统一社会信用代码

不适合作为“入驻商家双方协议”样本。《民法典》第四百六十四条把合同定义为民事主体之间的协议；同一主体不能通过左右互签形成两个独立当事人。它可以在网站真实开展自己的业务，但属于平台自营。《电子商务法》第三十七条明确要求平台将自营业务与平台内经营者业务显著区分并标注，不得误导消费者。

因此，可以把该企业作为“网站运营主体/自营业务资质”另外提交，但不要把它包装成第三方商户，也不要生成一份双方其实是同一统一社会信用代码的入驻协议。

### 2. 关联企业，但有不同统一社会信用代码

可以作为首批真实入驻商家。关键不是股东关系是否独立，而是它是否为真实、独立登记且实际承担协议权利义务的民事主体。操作上应满足：

- 在公示系统可查询，登记状态正常；
- 不同统一社会信用代码，协议主体名称与公章完全一致；
- 发布内容真实并与经营范围、行政许可相符；
- 使用真实企业账号，经办人有授权；
- 按与外部商家相同的流程审核，不因关联关系跳过步骤；
- 在向监管提交的说明中写明“该商家与平台存在关联关系，为平台首批试运行入驻企业”，避免造成独立第三方样本的误解。

若同一自然人是双方的法定代表人或控制人，实务上宜由双方分别授权不同经办人签署、分别加盖公章，并留存各自授权/内部同意文件。关联企业样本通常能够证明系统流程已真实运行，但若条件允许，再补充一家无关联的真实商户，证明力会更强。

## 六、“发布者完成实名、资质认证的后台截图”具体怎么交

### 监管意见的合理解读

该要求包含两个层次：

- **个人发布者**：证明账号在获得发布权限前已经完成真实身份认证。《网络安全法》第二十六条和《互联网用户账号信息管理规定》第九条是直接依据。
- **企业/机构发布者**：证明平台不仅识别了登录个人，还核验了其代表的企业主体、授权关系及与发布内容相关的许可/专业资质；属于平台商家的，还应同时满足《电子商务法》第二十七条和《网络交易监督管理办法》第二十四条。

“后台截图”不是要求公开用户证件，而是要求监管人员能从系统状态看出：哪个真实主体、哪次审核、由谁在何时通过、对应网站上的哪条信息。

### 推荐截图字段

每个样本建议截一张完整详情页，必要时再补一张审核日志页。应展示：

- 站点/后台名称和记录编号；
- 用户账号 ID（手机号、邮箱只保留必要脱敏部分）；
- 主体类型：个人 / 企业；
- 个人姓名脱敏显示、证件类型、证件号脱敏、实名状态、认证方式和认证完成时间；
- 企业法定全称、统一社会信用代码、登记状态、营业执照核验状态；
- 经办人是否实名、授权书是否核验；
- 相关行政许可/专业资质名称、编号（可局部脱敏）、有效期和核验状态；
- 官方核验渠道、最近核验时间、审核人、审核结论、下一次复核日期；
- 对应信息/店铺 ID、标题、线上 URL 或可核对的页面标识、发布状态；
- 审核日志中的“提交—补正（如有）—通过—开放发布权限”时间线。

### 隐私打码边界

普通整改表单截图中：

- **不得展示**完整身份证号码、身份证正反面原图、完整手机号、私人住址、银行卡、生物识别信息、账号密码或后台访问令牌；
- 姓名可显示为“张*”；身份证号只保留足以区分样本的少量首尾位，例如 `3301**********1234`；手机号显示为 `138****1234`；
- 企业法定名称、统一社会信用代码、登记状态等本就是依法公示和用于核验的企业主体信息，可为完成对应核验而展示；但营业执照扫描件、授权书中的个人签名/电话等仍应按最小必要原则处理；
- 管理员个人姓名可显示工号或脱敏姓名，避免无必要扩散员工个人信息。

平台内部应保存未脱敏原件并严格做权限控制和加密。只有监管部门明确要求查看完整证件时，才通过其指定的安全渠道单独提交，并在副本上增加“仅用于本次整改核验、不得用于其他用途”的水印；不要把完整身份证号或证件照片嵌入普通截图或公开网页。

## 七、最小可落地整改路径

1. 选择 1—2 家国家企业信用信息公示系统可查询、确有真实业务的企业；关联但不同主体的企业可先用，同一运营主体只能列为自营。
2. 让企业在网站以真实账号提交执照、必要许可、经办人实名和授权书。
3. 审核人员在官方公示系统人工查询，完成比对和留痕；不一致的先补正。
4. 双方盖章签署当前版本的商家入驻协议，或使用可靠电子签；在后台绑定协议版本和商家 ID。
5. 审核通过后再发布一条与实际业务一致的信息，并确保前台企业名称可与执照对应。
6. 分别导出“协议及证明材料包”和“脱敏后台审核截图”，把发布信息 URL、商家编号、企业名称贯穿全部材料。
7. 建立六个月复核提醒、退出后三年档案留存，以及每年 1 月和 7 月的平台内经营者信息报送流程。

按这一路径完成后，监管看到的将是一条闭环证据链，而不是孤立的营业执照或测试截图：

`可查询的真实企业 → 已签协议 → 已上传资质 → 人工官方核验 → 后台审核通过 → 获得发布权限 → 网站真实信息可对应 → 定期复核和留档`
